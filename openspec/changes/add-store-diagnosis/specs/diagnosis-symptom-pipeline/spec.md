## ADDED Requirements

### Requirement: 定时触发与数据就绪
系统 SHALL 支持每日 13:00 Cron 触发流程 A；ensure_data_ready MUST 轮询数据就绪（30 分钟超时 ×3），最终失败置 FAILED 并落事件。

#### Scenario: 数据未就绪
- **WHEN** 轮询超过 30 分钟 ×3 仍无数据
- **THEN** run 进入 FAILED，事件流水记录失败原因

### Requirement: 快照与可重放
取数结果 MUST 按一店一文件快照（schema v2）落库，周期解析由确定性代码完成；相同输入 SHALL 产出一致的症状结论，报告与图表数字 MUST 只来自快照原文。

#### Scenario: 同输入重放
- **WHEN** 对同一快照重复执行症状规则引擎
- **THEN** 输出的症状结论完全一致

### Requirement: 阈值规则引擎
症状判定 MUST 全部代码化：10 项二级指标的阈值命中、环比、共性标记（命中率 ≥40%）、个体分级（P0：个体权重 ≥30% 或绩效分 <3.5；P1：15%~30%；P2：<15%）与影响度（权重 × 命中率）排序 SHALL 与手算一致；阈值 MUST 配置化（thresholds.json）。C-S09、C-S12、C-S13 的验收常量见 `diagnosis-promoted-contracts`：来源 A 为 ≥10% / <90% / <95%。本规格原先的「C-S09 ≥2%、C-S12 <90%、C-S13 <95%」只作参照，不是验收常量。环比的计算公式、窗口合计口径与下滑分档 MUST 遵循本规格的「环比计算口径」和「恶化方向与下滑分档」，不在阈值引擎内另定日均或日比率均值。这三项以外的绝对阈值百分数，验收仍以飞书需求文档正文为准。

#### Scenario: 阈值命中判定
- **WHEN** 某店延迟发货率为 12.5%（验收阈值 ≥10%）
- **THEN** 该指标命中异常，并按权重与命中率参与影响度排序

#### Scenario: 阈值调整不改框架
- **WHEN** thresholds.json 调整某指标阈值
- **THEN** 无需修改框架代码即可生效

### Requirement: 健康店分流
症状正常的店铺 MUST 被标记 SKIPPED，不进入流程 B 归因下钻。健康判定 MUST 只统计 `fetchable=true` 的诊断范围内指标。`fetchable=false` 的黄标指标不构成异常，也不充当健康证据。

#### Scenario: 健康店不做工
- **WHEN** 某店全部可取数指标未越阈
- **THEN** 该店 item 为 SKIPPED 且不创建归因会话

#### Scenario: 仅黄标不可取数仍视为健康
- **WHEN** 某店全部可取数指标未越阈，且库存、推广 roas、流量异常（建议调价未调价）、流量异常SPU数占比、推广 Roas 均为 SKIP
- **THEN** 该店 item 为 SKIPPED，且不因黄标指标没有数值而进入归因

### Requirement: Q1~Q5 查询口径
取数 MUST 覆盖 Q1 主体汇总 / Q2 店铺快照 / Q3 近 60 天评分趋势 / Q4 二级指标快照 / Q5 三个月指标趋势；时间口径（最新分区、不含今天、最近 60 天 / 3 个月）与展示形态 SHALL 符合数据契约。

#### Scenario: 趋势窗口
- **WHEN** 执行 Q3 查询
- **THEN** 返回最近 60 天（不含今天）的日粒度评分趋势

### Requirement: 环比计算口径
症状管线计算周期环比时 MUST 使用 `(本期值 - 上期值) / 上期值 × 100%`。等长 7 天窗口 MUST 使用周期合计：累计指标直接比较两侧窗口累计值。比率指标 MUST 先在各自窗口内计算 `sum(分子) / sum(分母)`，再把两个比率代入环比公式。系统 MUST NOT 使用各日比率的算术平均，包括两侧天数不等的情况。累计指标仅当对比两侧天数不同时，MUST 先将两侧换算为日均（窗口合计 / 天数）再代入环比公式。上期值为 0 或缺失，或比率分母合计为 0 时，该环比 MUST 标为不可计算，并且 MUST NOT 写入数值。

本需求绑定飞书需求文档 `https://ucnbkepnx9u9.feishu.cn/docx/GTPJdXujnom2WnxgUFVcU2Bonsb`（验收 SoT）与用户 2026-10-16 确认的环比截图。架构 wiki 不是本口径的验收依据。

#### Scenario: 等长窗口用累计
- **WHEN** 曝光两侧都是 7 天，本期累计 700，上期累计 1000
- **THEN** 环比为 (700 − 1000) / 1000 × 100% = −30%，计算使用累计值 700 与 1000

#### Scenario: 比率用周期合计
- **WHEN** 本期 7 天退货订单为 0、0、0、0、0、4、10（合计 14），订单为 10、10、10、10、10、50、100（合计 200），上期 7 天退货订单合计 10、订单合计 200
- **THEN** 本期退货率为 14/200，上期退货率为 10/200，环比为 (0.07 − 0.05) / 0.05 × 100% = 40%，并且不使用本期各日退货率的算术平均

#### Scenario: 累计指标在天数不等时用日均
- **WHEN** 本期 7 天曝光累计 700，对比期 6 天曝光累计 600
- **THEN** 两侧日均为 100 与 100，环比为 0%

#### Scenario: 比率在天数不等时仍用合计比率
- **WHEN** 本期 7 天退货订单合计 14、订单合计 200，上期 6 天退货订单合计 6、订单合计 120
- **THEN** 本期比率为 14/200，上期比率为 6/120，环比按这两个比率计算，并且两侧都不使用日比率的算术平均

#### Scenario: 上期不可除时不产生环比数值
- **WHEN** 上期累计值为 0，或上期比率分母合计为 0，或上期值缺失
- **THEN** 该指标环比标记为不可计算，快照与症状结论中没有该环比的数值

### Requirement: 恶化方向与下滑分档
下滑分档 MUST 按指标好坏方向衡量恶化，而不是把环比为负一律视为恶化。负向指标（退货率、投诉率）上升为恶化；正向指标（曝光、连带率、回复率）下降为恶化。恶化幅度 w MUST 取恶化方向上的变化百分比：正向指标 w = −环比，负向指标 w = 环比。分档 MUST 唯一：

- 5% ≤ w < 10%：轻微下滑
- 10% ≤ w ≤ 20%：一般下滑
- w > 20%：严重下滑
- w < 5%：不进入下滑分档

−10% 归入一般下滑，−20% 仍属一般下滑，严格大于 20% 的恶化为严重下滑。规格用词采用环比截图的「轻微 / 一般 / 严重」；「中度」与一般同档，「重度」与严重同档。好转方向的变化 MUST NOT 标为下滑。飞书需求文档是验收 SoT；若其正文给出不同的分档百分数，MUST 先修订本规格再实现。在需求文档正文未另给分档数字时，以上截图分档为绑定规则。架构 wiki 不覆盖本分档。

#### Scenario: 正向指标按跌幅分档
- **WHEN** 曝光环比分别为 −7%、−10%、−20%、−21%、−4%
- **THEN** 依次判定为轻微下滑、一般下滑、一般下滑、严重下滑、不进入下滑分档

#### Scenario: 负向指标上升才是恶化
- **WHEN** 退货率环比分别为 +12% 与 −12%
- **THEN** +12% 判定为一般下滑，−12% 不进入下滑分档

### Requirement: 指标可取数性
飞书看板黄格 MUST 按下列原文逐项标记 `fetchable=false`，并在症状管线中 SKIP。早先口头子集不替代本清单：

1. 库存
2. 推广 roas
3. 流量异常（建议调价未调价）
4. 流量异常SPU数占比
5. 推广 Roas

「推广 roas」与「推广 Roas」MUST 都保留为黄格，MUST NOT 互相替代，也 MUST NOT 改写成看板上没有的「推广ROAS」。单独的「流量异常」MUST NOT 代替第 3 项或第 4 项。这五项 MUST NOT 被写入猜测值、代理值、样例值或模型补数，也 MUST NOT 参与越阈、环比或影响度。其余诊断范围内指标 MUST 通过 data_agent 语义层口径与受控 SQL 模板取数（指标白名单、字段白名单、参数绑定、分区裁剪）。该链路 MUST NOT 移植 RAG 运行时，MUST NOT 由 LLM 生成或改写 SQL。可取数指标查询失败时 MUST 显式标记数据不足或节点失败，并且 MUST NOT 改记为 `fetchable=false`。实现 MUST NOT 自行扩大或缩小这份黄标集合。

#### Scenario: 黄标指标跳过
- **WHEN** 症状引擎遇到库存、推广 roas、流量异常（建议调价未调价）、流量异常SPU数占比或推广 Roas
- **THEN** 五项均为 `fetchable=false`，不产生数值，不参与越阈与环比

#### Scenario: 非黄标指标走受控取数
- **WHEN** 诊断范围内的非黄标指标进入流程 A
- **THEN** 系统按语义层口径和受控 SQL 模板取得该指标的窗口合计，或比率所需的分子合计与分母合计；取数过程不调用 RAG 检索，也不由模型生成 SQL

#### Scenario: 取数失败不编造
- **WHEN** 非黄标指标的受控查询失败或无返回
- **THEN** 该指标标记为数据不足或对应节点失败，症状结论与报告中不出现为它编造的数值
